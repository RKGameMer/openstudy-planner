# 1. 开发阶段总览

## 1.1 MVP核心闭环

第一版只实现并验证以下闭环：

> 创建任务 → 选择今日重点 → 开始执行 → 标记结果 → 对未完成任务重新决策

所有开发任务都必须直接服务于该闭环、本地数据控制或第一版发布质量。

## 1.2 优先级定义

### P0

第一版发布必须完成。

任何P0任务未完成或未通过验收，MVP均不能标记为完成。

### P1

不增加产品功能的质量改进。

P1只能在主要P0功能稳定后进行，不得以P1任务为理由扩大MVP范围。

## 1.3 开发阶段与依赖顺序

| 阶段  | 目标         | 对应任务            |
| --- | ---------- | --------------- |
| 阶段A | 项目初始化和数据基础 | DEV-001—DEV-006 |
| 阶段B | 基础任务管理     | DEV-007—DEV-010 |
| 阶段C | 今日重点和状态管理  | DEV-011—DEV-016 |
| 阶段D | 从现在重新安排    | DEV-017—DEV-024 |
| 阶段E | 数据导出、导入和清除 | DEV-025—DEV-029 |
| 阶段F | 页面适配和状态覆盖  | DEV-030—DEV-031 |

总体依赖顺序：

```text
项目初始化
→ 统一任务数据模型
→ 浏览器本地存储
→ 基础任务业务规则
→ 新建、编辑和任务库
→ 今日重点
→ 状态管理和任务移除
→ 从现在重新安排
→ 数据导出、导入和清除
→ 手机和桌面适配
→ 测试
→ README、隐私和发布核查
```

## 1.4 全局范围限制

以下功能不得出现在任何第一版任务中：

* 番茄钟或专注倒计时；
* 日历拖拽或复杂日程排程；
* AI规划、AI建议或AI自动拆分；
* 成绩预测和录取概率预测；
* 用户注册、登录和账户系统；
* 云端数据库和云同步；
* 社交、排行榜和连续打卡；
* 自动推送、邮件或系统提醒；
* 复杂统计图表；
* 强制学习时长记录；
* 精确分心、中断和情绪记录；
* PWA安装；
* 深色模式；
* 打印功能；
* 科目专用复杂表单；
* 今日重点任务硬数量限制；
* 延期任务硬数量限制；
* 未完成任务自动无限顺延。

# 阶段A：项目初始化和数据基础

## DEV-001 建立项目基础结构

* **任务编号：** DEV-001
* **任务名称：** 建立MVP项目基础结构
* **优先级：** P0
* **开发目标：** 建立能够承载页面、业务逻辑、本地数据访问、测试和项目文档的基础工程结构。
* **前置依赖：** 无。
* **包含范围：**

  * 建立应用入口；
  * 建立页面、通用组件、数据模型、数据访问、业务逻辑、测试和文档目录；
  * 建立本地开发和正式构建命令；
  * 建立基础版本信息；
  * 建立忽略本地文件、备份文件和敏感文件的规则；
  * 建立基础错误捕获入口。
* **不包含范围：**

  * 不实现具体业务功能；
  * 不建立后端服务；
  * 不建立账户系统；
  * 不连接云端数据库；
  * 不接入统计、广告或追踪工具；
  * 不配置PWA。
* **验收标准：**

  1. 项目可以在本地正常启动；
  2. 项目可以完成正式构建；
  3. 页面、数据、业务和测试代码具有明确目录边界；
  4. 仓库中不存在真实用户数据、密钥或导出备份；
  5. 默认应用入口可以正常打开；
  6. 项目初始化过程中没有加入MVP范围外功能。
* **可能风险：**

  * 过早引入复杂架构；
  * 使用过多第三方依赖；
  * 项目结构无法支持后续独立测试。

## DEV-002 定义统一任务数据模型

* **任务编号：** DEV-002
* **任务名称：** 定义统一任务数据结构和枚举
* **优先级：** P0
* **开发目标：** 建立所有科目和学习形式共用的单一任务数据模型。
* **前置依赖：** DEV-001。
* **包含范围：**

  * 任务ID；
  * 任务名称；
  * 科目；
  * 学习形式；
  * 内容范围；
  * 下一步先做什么；
  * 完成标准；
  * 计划日期；
  * 今日重点日期；
  * 状态；
  * 备注；
  * 可选实际用时；
  * 可选实际完成情况；
  * 创建时间；
  * 更新时间；
  * 数据格式版本。
* **不包含范围：**

  * 不建立不同科目的独立数据结构；
  * 不增加启动延迟、分心次数、中断次数和情绪字段；
  * 不增加诊断或健康字段；
  * 不建立成绩预测字段；
  * 不建立复杂父子任务系统；
  * 不建立用户账户字段。
* **验收标准：**

  1. 用户创建普通任务时只有任务名称必填；
  2. 新任务默认状态为“待处理”；
  3. 科目只包含语文、数学、英语、其他；
  4. 学习形式只包含录播课、直播课、自学、刷题、复习、测试、其他；
  5. 状态只包含待处理、进行中、部分完成、已完成、已移除；
  6. “延期”不属于任务状态；
  7. 所有科目共用相同字段结构；
  8. 所有可选字段允许为空。
* **可能风险：**

  * 数据字段继续扩大；
  * 将可选字段错误设为必填；
  * 混淆计划日期和今日重点日期。

## DEV-003 建立浏览器本地数据访问层

* **任务编号：** DEV-003
* **任务名称：** 实现浏览器本地数据保存、读取和清除接口
* **优先级：** P0
* **开发目标：** 为全部任务功能建立统一、可测试的本地数据访问层。
* **前置依赖：** DEV-002。
* **包含范围：**

  * 初始化本地数据；
  * 读取全部任务；
  * 按ID读取任务；
  * 新增任务；
  * 更新任务；
  * 永久删除任务；
  * 完整替换数据；
  * 清除应用控制的本地数据；
  * 保存数据格式版本；
  * 返回存储不可用、容量不足和写入失败错误；
  * 保护旧数据不被不完整写入覆盖。
* **不包含范围：**

  * 不连接云端数据库；
  * 不实现多设备同步；
  * 不上传任务正文；
  * 不自动备份到服务器；
  * 不建立账户隔离；
  * 不单独实现只读运行模式。
* **验收标准：**

  1. 新建任务后刷新网页，任务仍然存在；
  2. 编辑任务后刷新网页，修改内容仍然存在；
  3. 永久删除任务后刷新网页，任务不会重新出现；
  4. 清除应用数据后重新打开网页，应用显示为空；
  5. 关闭并重新打开同一浏览器后，已保存任务仍然存在；
  6. 存储失败时不得显示保存成功；
  7. 存储失败时不得静默丢弃用户正在编辑的内容；
  8. 写入失败时旧数据不得被不完整的新数据覆盖；
  9. 完整替换失败时不得产生部分导入结果；
  10. 正常任务操作不得发送包含任务正文的网络请求。
* **可能风险：**

  * 浏览器禁用本地存储；
  * 隐私模式行为不同；
  * 写入中断导致数据损坏；
  * 本地数据容量不足。

* **任务编号：** DEV-005
* **任务名称：** 建立表单校验、操作反馈和危险操作确认
* **优先级：** P0

* **包含范围：**

  * 非阻断成功提示；
  * 操作失败提示；
  * 字段校验错误；
  * 重试入口；
  * 取消入口；
  * 永久删除确认；
  * 导入替换确认；
  * 清除本地数据确认；
  * 失败时保留表单输入。
* **不包含范围：**

  * 不加入推送通知；
  * 不加入系统提醒；
  * 不加入奖励动画；
  * 不加入连续打卡反馈；
  * 不加入羞辱、惩罚或焦虑文案。

* **可能风险：**

  * 不同页面提示不一致；
  * 错误信息泄露内部细节；
  * 危险操作过于容易触发。

  * 日期和状态规则不一致；
  * 不同页面查询结果不同。

# 6. 开发清单质量检查

## 6.1 依赖顺序

清单已经按照以下顺序排列：

> 项目初始化 → 数据模型 → 本地存储 → 基础任务管理 → 今日重点 → 状态管理 → 重新安排 → 数据管理 → 页面适配 → 测试和文档

不存在先实现重新安排、再建立任务数据结构的情况。

## 6.2 任务粒度

以下功能均已独立拆分：

* 数据模型；
* 本地存储；
* 分类组件；
* 新建任务；
* 编辑任务；
* 任务库；
* 今日重点；
* 状态转换；
* 任务移除；
* 六种重新安排方式；
* 导出；
* 导入校验；
* 导入替换；
* 数据清除；
* 响应式适配；
* 各类测试。

不存在“完成整个任务管理系统”这种无法独立验收的任务。

## 6.3 重复任务

* 页面功能任务负责实现具体状态；
* DEV-005负责通用反馈组件；
* DEV-031只检查和补齐覆盖，不重新开发状态系统；
* 数据层测试、业务测试和页面测试已经分开；
* 已移除功能和重新安排中的移除入口职责不同。

## 6.4 MVP范围

本清单没有加入：

* 番茄钟；
* 日历拖拽；
* AI建议；
* 成绩预测；
* 用户账户；
* 云端数据库；
* 复杂图表；
* 连续打卡；
* 自动推送提醒。

## 6.5 必填字段

普通任务只有任务名称为用户必填。

以下字段全部保持可选：

* 科目；
* 学习形式；
* 内容范围；
* 下一步；
* 完成标准；
* 计划日期；
* 备注；
* 实际用时；
* 实际完成情况。

## 6.6 个人偏好与硬规则

“今日重点1—3项”只作为默认建议。

产品：

* 不阻止添加更多重点；
* 不强制三科平均分配；
* 不强制记录时长；
* 不强制打卡；
* 不限制延期数量；
* 不根据任务数量评价用户；
* 不自动判断用户是否自律。

# 7. MVP开发完成定义

只有同时满足以下条件，MVP才可标记为完成：

1. DEV-001至DEV-041全部完成并通过验收；
2. 用户可以完成完整核心闭环；
3. 普通任务只填写名称即可创建；
4. 今日重点没有硬数量上限；
5. 未完成任务不会自动顺延；
6. 六种重新安排操作全部可用；
7. 本地存储失败不会静默丢失数据；
8. 导入失败不会覆盖现有数据；
9. 用户可以导出和清除本地数据；
10. 手机和桌面均可完成核心流程；
11. 隐私说明与实际实现一致；
12. 正常使用不上传任务正文；
13. README没有宣传未实现功能；
14. 发布前范围检查未发现MVP外功能。
